Ticket Workflow Framework

An autonomous Linear-ticket → GitHub-PR pipeline built from role-specialized Claude Code subagents. Each agent runs on a model tier matched to its cognitive load; each ticket is worked A→Z in its own git worktree.

Visual companion to TICKET-WORKFLOW.md (this project directory) · the agent & command files in ~/.claude/ are the source of truth

Opus — reasoning & decisions Sonnet — execution & checks Haiku — external API calls You

The shape of a run

  1. /wf-prime — once per repo. Writes a reusable CONTEXT.md operating manual.
  2. /wf-spec ENG-12 ENG-13 — interactive. Refine each ticket into a real spec, posted as a comment on its Linear ticket (description becomes a short brief).
  3. /wf-run ENG-12 ENG-13 — autonomous. Each ticket → an open PR, ticket set In Review.
  4. You review & merge the PR.
  5. Tell it "ENG-12 is merged" — only now does it set Done and clean up the worktree.

The 5 Commands

/wf-primeonce per repo

wf-cartographer writes CONTEXT.md — the durable, reusable operating manual. Highest leverage-per-token move.

/wf-specrun first · interactive

Refines each ticket with you (one at a time) and posts the spec as a marked comment on its Linear ticket; the description becomes a short brief. Ticket stays in To Do.

/wf-runautonomous · seq or --parallel

Each ticket A→Z in its own worktree: In Progress → plan → build → review → verify → open PR → In Review. --parallel runs file-disjoint tickets concurrently (≤3) via wf-runner.

/wf-evalregression gate · offline

Stage-evals the planner & executor over seed cases, judged by wf-judge vs a baseline. Run after tuning any agent/model.

/wf-calibratevalidates the judge · offline

Grades wf-judge against a human-labeled gold set (agreement, FAIL precision/recall, bias probes) so the /wf-eval gate can be trusted. Re-run after changing the judge.

Same hard rules as sequential — safe only because each ticket owns a disjoint worktree, and the overlap guard keeps file sets non-intersecting. All Linear/GitHub mutations stay with the orchestrator; runners never touch them.

On mergeonly when you say “ENG-123 is merged”
wf-github PR_STATUSconfirms MERGED → wf-linearDone→ worktree + branch removed

The pipeline never merges, waits for checks, or sets Done on its own. Cleanup happens only after you confirm — and only once wf-github confirms MERGED. A failed ticket keeps its worktree for inspection.

Smart & cheap — the context strategy

Distill · target · cache · pass-forward — never dump, broadcast, re-derive, or regenerate.

Pass forward, don't re-derive

The Opus planner explores once and hands a Context Pack downstream. Executor/reviewer/verifier inherit it instead of re-reading the repo every loop — net token savings.

Amortized manual

CONTEXT.md is built once and reused across every ticket in every run. Personas live in cached system prompts → ~free at runtime.

Single-owner boundaries

Only wf-linear / wf-github touch external systems. The orchestrator pre-fetches and passes data down, keeping every other agent plumbing-free.

Self-improving

SPEC_GAPS teaches the wf-spec-builder; MANUAL_DRIFT nudges you to re-prime when CONTEXT.md goes stale. The system flags its own gaps.

Security & sandboxing

Untrusted ticket text in + arbitrary test/build execution = a "lethal trifecta". All project code runs sandboxed.

wf-exec wrapper

Runs project code under a macOS seatbelt profile: external network blocked (loopback OK for local tests), and ~/.ssh/~/.aws/~/.gnupg/gh creds unreadable. A malicious test or postinstall can't phone home.

Executor & verifier comply

Every test/build/lint/install runs through wf-exec. New dependencies are surfaced to you before merge.

Enforcement hook

A PreToolUse guard blocks unwrapped test/build commands in a worktree — defense-in-depth, not just instructions. Fails open on any uncertainty; ignores git/gh.

Egress only at the edges

Only wf-linear/wf-github reach the network (Linear/GitHub). Nothing else does.

Design-handoff ingestion

File-embeds on a ticket are downloaded by the orchestrator via wf-fetch-handoff (Linear-host allowlist, https-only, size-capped, zip-slip-guarded) into a path outside the worktree — never in the diff. Strictly reference-only: agents recreate the intent, never copy its files.

Evals — the regression gate

/wf-eval catches silent quality drops when you tune a prompt, model, or the flow. Fully offline.

Fixtures

Tiny dependency-free git repos (node-toy, py-toy) whose stdlib tests run inside the no-network sandbox. Reset clean between stages.

Seed cases + rubrics

Four: node-feature, node-bugfix, py-feature, and ambiguous-spec — which checks the planner refuses to invent scope (and stays non-interactive in eval mode).

Stage evals

plan judges the planner's output; execute judges the executor's diff + whether the fixture tests actually pass (sandboxed).

Judge + baseline

wf-judge scores each (gate, then 0–1, weighting observed test results highest); the runner flags regressions vs the saved baseline (PASS→FAIL or score drop > 0.15).

Trusting the judge

/wf-calibrate grades wf-judge against a human-labeled gold set — agreement (bar ≥90%), FAIL precision/recall, bias probes — so the gate itself is trustworthy. Re-run after changing the judge.

Firm invariants

  • Never merges, waits for checks, or sets Linear Done autonomously — that needs your explicit go-ahead, after wf-github confirms MERGED.
  • Branch naming ticket-id/slug; worktrees in ROOT/.worktrees/ — kept on failure, removed on merge.
  • Each ticket isolated in its own worktree — sequential by default, or concurrent under --parallel (≤3, file-disjoint) — never PR-stacked on another ticket's unmerged work.
  • Refined spec is posted as a marked Linear ticket comment (latest wins); the description holds a short brief — no .planning/ files anywhere.
  • PR descriptions are concise & high-fidelity (What / Why / Changes / Verification). No filler.
  • All project code runs sandboxed via wf-exec; executor commits carry a Co-Authored-By: Claude trailer.
  • Every agent embeds the same engineering discipline: surgical, simple, goal-driven.
